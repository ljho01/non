# Non

데스크톱 전용, 로컬 우선 노트 · PDF · AI 공간입니다. 실행하면 운영체제의 **문서/non** 폴더를 자동으로 만들고 엽니다. 가운데 여러 문서 탭, 오른쪽 AI 대화를 둡니다. Electron의 Chromium + Node.js 런타임으로 macOS Apple Silicon에서 개발·패키징합니다. 웹 배포판은 없습니다.

## 실행

필요 환경: Bun. 앱 실행 파일에는 Electron의 Chromium과 Node.js가 함께 들어가므로 사용자 환경에는 Bun이나 Rust가 필요하지 않습니다.

```sh
bun install
bun run dev
```

UI만 작업할 때는 Electron을 띄우지 않고 브라우저 샘플 볼트와 HMR을 사용할 수 있습니다.

```sh
bun run dev:web
```

이 명령은 브라우저에서 `http://127.0.0.1:1420/scripts/preview-index.html`을 엽니다. 샘플 노트의 열기·편집·저장은 메모리에서 동작하므로 실제 `문서/non` 파일을 건드리지 않습니다. 네이티브 파일시스템, PDF, 계정 인증, AI 에이전트 IPC를 변경한 경우에만 `bun run dev`로 Electron 최종 확인이 필요합니다. 브라우저 개발 서버는 제품 웹 버전이 아닙니다. 로컬 앱 패키지:

```sh
bun run build
```

결과는 `release/mac-arm64/Non.app`입니다. 현재 설정은 로컬 검증용 unsigned 디렉터리 패키지이며 외부 배포용 Developer ID 서명·공증은 별도 작업입니다.

## 창과 설정 화면

공통 타이틀바 행 없이 콘텐츠가 창 위까지 이어집니다. macOS 창 버튼은 유지하며 사이드바 상단 또는 문서 헤더의 빈 공간을 잡아 이동할 수 있습니다. 투명 Electron 창과 macOS `sidebar` vibrancy를 사용하고, 문서 영역은 불투명하게 유지합니다. 테마 변경은 Chromium UI와 네이티브 창에 함께 적용됩니다.

왼쪽 폴더 사이드바 경계를 드래그하면 232–420px 사이에서 너비를 조절할 수 있으며 재실행 후에도 유지됩니다. 경계는 호버·드래그·키보드 포커스 중에만 중앙이 진하고 위아래로 흐려지는 1px 선으로 강조됩니다. 구분선에 포커스한 뒤 좌우 방향키로 조절하거나 더블 클릭으로 기본 너비로 되돌릴 수 있습니다.

사이드바는 Codex 데스크톱 앱의 정보 밀도를 기준으로 `sm` 텍스트, 28–34px 항목 높이, 8px 바깥 여백을 사용합니다. 선택 상태는 글자 굵기를 바꾸지 않고 낮은 대비의 둥근 배경으로 표시하며, 열린 폴더는 별도 펼침 화살표 대신 폴더 아이콘 상태로 구분합니다.

앱의 고정 UI 타이포그래피는 Tailwind의 `xs / sm / base / lg / 2xl / 3xl` 크기와 명명된 굵기·행간·자간·폰트 패밀리 토큰만 사용합니다. 노트와 Markdown의 상대적인 제목·코드 배율도 `styles.css`의 문서용 의미 토큰으로 관리하며, 문서 본문은 별도 설정 없이 `base` 토큰을 사용합니다.

설정은 앱 창 전체를 채우는 화면으로, 일반 / AI 계정 / 스킬 / 데이터 및 기억 / 앱 정보 메뉴가 있습니다. AI 계정에서 에이전트 샌드박스를 전환할 수 있으며 기본값은 켜짐입니다. 켜면 파일 도구를 `문서/non` 내부로 제한하고, 끄면 절대경로를 포함한 다른 로컬 경로의 UTF-8 파일도 읽고 생성·수정할 수 있습니다. 샌드박스를 꺼도 셸 실행은 허용하지 않습니다. 돌아가기 또는 Escape로 원래 작업 화면에 복귀합니다. ChatGPT 앱의 디자인을 요청받아 중립 색상·반투명 사이드바·전체 화면 설정으로 변경했지만, 원본 앱 캡처는 Mac 잠금으로 얻지 못했으므로 픽셀 단위 재현을 검증한 상태는 아닙니다.

## 폴더와 문서

1. 실행하면 운영체제의 문서 폴더 아래 소문자 `non`을 자동 생성하고 유일한 작업 루트로 엽니다. 폴더 선택 화면 없이 그 아래에서 바로 노트와 하위 폴더를 만들 수 있습니다.
2. 왼쪽 **파일** 제목을 누르면 현재 파일 트리만 접히거나 펼쳐집니다. 제목 행에 포인터를 올리면 나타나는 `+`는 `문서/non` 루트에 새 JSON 노트를 즉시 만듭니다. 다른 루트를 고르거나 추가하는 메뉴는 표시하지 않습니다.
3. 새 노트나 PDF는 현재 선택한 하위 폴더에 들어가며 기존 빈 폴더도 트리에 표시합니다.
4. **새 노트**를 클릭하거나 `⌘N`을 누르면 선택한 폴더에 `Untitled.note.json`을 즉시 만들고 엽니다. 이름이 있으면 `Untitled 2`, `Untitled 3` 순서로 안전하게 증가합니다. 새 노트 버튼을 우클릭하면 shadcn 컨텍스트 메뉴에서 JSON 또는 Markdown을 선택할 수 있습니다. Markdown은 `Untitled.md`로 만듭니다.
5. 외부 수정과 충돌하면 버퍼를 보존하고 **복사본 저장**을 안내합니다. 복사본은 새 문서·블록 ID를 부여합니다.
6. 기존 Markdown도 열고 수정할 수 있습니다. JSON으로 자동 변환하지 않습니다. 일반 설정 JSON은 노트 목록에서 제외합니다.
7. PDF 문맥은 현재 페이지의 추출 텍스트입니다. 스캔 PDF OCR이나 전체 PDF 색인은 아직 없습니다.

왼쪽 **최근 항목**에는 `문서/non`에서 최근에 연 문서 6개를 표시하며 제목을 눌러 목록을 접거나 펼칠 수 있습니다. 제목 행에 포인터를 올리면 나타나는 `+`는 `문서/non` 루트에 새 JSON 노트를 즉시 만듭니다. 같은 문서는 중복되지 않습니다. 이미 상위 5개 안에 있는 문서는 다시 열거나 편집해도 현재 순서를 유지하고, 6위 이하 또는 새 문서만 맨 위로 올라옵니다. JSON은 문서 제목, Markdown은 첫 `#` 제목, PDF는 파일명을 표시합니다. 최근 기록은 최대 12개를 기기 로컬에 보관합니다.

가운데 문서 탭은 dnd-kit의 포인터·키보드 정렬을 지원합니다. 바꾼 순서는 루트 폴더별 열린 탭 상태에 함께 저장되어 다시 열어도 유지됩니다.

단축키: `⌘B` 왼쪽 폴더 사이드바, `⌘J` 오른쪽 AI 패널, `⌘N` 새 노트, `⌘K` 제목·본문 찾기, `⌘S` 저장, `⌘W` 탭 닫기, `⌘,` 설정. `Mod+1`–`Mod+8`은 해당 순서의 문서 탭, `Mod+9`는 마지막 문서 탭으로 이동합니다. `Mod+B`·`Mod+J`·`Mod+K`·탭 전환은 TanStack Hotkeys를 사용하므로 macOS에서는 Command, Windows/Linux에서는 Control로 동작합니다. 테마는 라이트·다크·시스템 자동을 지원합니다.

## 로컬 오디오 전사

왼쪽 **새 전사**를 누르면 입력과 언어를 고르는 모달이 열립니다. 입력은 Mac 마이크를 듣는 실시간 전사와 오디오·영상 파일 중에서, 언어는 한국어와 English 중에서 선택할 수 있습니다. 세션이 하나 이상 있을 때만 왼쪽에 **전사 세션** 섹션이 나타나고, 세션을 열면 문서와 같은 중앙 탭에서 준비/전사/문장 정리/완료 상태, 처리 위치, 마이크 녹음 상태 또는 원본 오디오 재생을 확인할 수 있습니다. 자막은 Qwen live 이벤트의 오디오 시각을 타임스탬프로 보존하며 현재 문장을 아래에서 크게 보여 주고, 확정된 문장은 위로 이동하며 점차 흐려집니다. 녹음이 끝난 뒤 타임스탬프를 누르면 해당 위치부터 다시 재생됩니다. 실행 중인 세션은 중지할 수 있고, 중지·완료된 세션은 언어를 바꾸거나 다시 시작할 수 있습니다.

전사 엔진은 [`ljho01/qwen3-asr-opt`](https://github.com/ljho01/qwen3-asr-opt)의 고정 q8/MLX live 프로필을 사용합니다. Apple Silicon과 macOS 15 이상이 필요하며 `uv`, FFmpeg가 PATH 또는 표준 Homebrew 경로에 있어야 합니다. 첫 세션에서 런타임 설치를 누르면 검토한 커밋을 앱 데이터에 고정해 내려받고, 공식 Qwen3-ASR 1.7B 체크포인트의 고정 revision을 다운로드한 다음 q8로 변환합니다. q8 산출물을 검증한 뒤 원본 체크포인트는 자동으로 삭제합니다. 모델을 앱 패키지에 포함하지 않으므로 첫 설치는 수 GB 다운로드와 변환 시간이 필요할 수 있습니다.

원본 오디오는 사용자가 선택한 위치에서 읽기만 하며 복사하거나 수정하지 않습니다. 실시간 모드는 모델 준비가 끝난 뒤 macOS 기본 마이크를 FFmpeg AVFoundation으로 한 번만 읽습니다. 같은 입력에서 Qwen에는 16 kHz mono PCM을 보내고, 보관본은 음성 재생에 충분한 AAC 64kbps `.m4a`로 동시에 압축해 WAV 대비 약 75% 작게 저장합니다. 녹음은 세션 앱 데이터에 저장되어 중지·완료 뒤 재생할 수 있으며, 최초 사용 시 macOS 마이크 권한이 필요합니다. 세션 메타데이터·append-only 전사 출력·녹음·모델은 `~/Library/Application Support/Non/transcription/`에 두고 `문서/non`이나 iCloud 작업 폴더에는 넣지 않습니다. renderer에는 원본 절대경로나 모델 경로를 전달하지 않고 세션 ID 기반 IPC와 `non-audio://` 스트림만 노출합니다.

## AI 연결과 이미지 입력

오른쪽 상단에는 Arky의 상호작용을 참고한 AI 대화 탭 바가 있습니다. 한 폴더에서 최대 5개 런타임을 열고 전환·닫기·드래그 정렬할 수 있으며, 각 탭의 메시지·초안·첨부·오류·스트리밍 상태는 독립적으로 유지됩니다. 프런트엔드는 TanStack AI의 `useChat`이 메시지 조립·로딩·오류·중지를 관리하고, custom `ConnectConnectionAdapter`가 Electron IPC 이벤트를 AG-UI 스트림으로 변환합니다. 응답 중 다른 탭으로 이동해도 실행 중인 스트림은 해당 탭에 계속 쌓입니다. 로컬 pi Node 유틸리티 프로세스는 현재 응답을 한 번에 하나만 실행하므로 다른 탭에서는 초안을 작성할 수 있지만, 기존 응답이 끝나거나 중지되기 전에는 새 요청을 보내지 않습니다. 열린 AI 탭 순서와 활성 탭은 폴더별로 기기 로컬에 복원됩니다.

AI 계정 설정에는 ChatGPT Plus/Pro, Claude Pro/Max, OpenAI API 키, Anthropic API 키가 독립된 인증 소스로 표시됩니다. ChatGPT와 Claude 구독은 브라우저 OAuth로 연결하고, BYOK는 macOS의 숨김 입력 대화상자에서 받습니다. Claude 구독은 Arky와 같은 Claude Code 구독 경로를 사용하며 지원 모델을 Claude Opus 5와 Sonnet 5로 제한합니다. Anthropic API 키는 Fable 5.1도 선택할 수 있습니다. 모델 키에는 인증 소스를 함께 기록하므로 같은 모델 이름이라도 구독과 API 키를 구분합니다.

API 키와 OAuth 토큰은 renderer나 TanStack AI의 브라우저 keyring에 저장하지 않습니다. Electron main의 `safeStorage`로 전체 자격증명 묶음을 암호화하고 앱 데이터의 `ai-credentials.bin`에 `0600` 권한으로 저장하며, 복호화된 값은 main과 pi 유틸리티 프로세스 사이의 전용 IPC에서만 이동합니다. 기존 단일 `credentials.json`은 첫 로드 때 ChatGPT 자격증명으로 암호화 마이그레이션한 뒤 제거합니다.

AI 메시지에 PNG·JPEG·WebP·GIF 이미지를 파일 선택, 드래그 앤 드롭, 붙여넣기로 첨부할 수 있습니다. 텍스트 없이 이미지만 보내는 것도 지원합니다. 전송 전 미리보기와 개별 제거, 전송 후 사용자 메시지 내 이미지 표시, 대화 재실행 시 복원을 제공합니다.

이미지는 한 번에 최대 5개, 개당 10MB, 합계 20MB까지이며 UI와 로컬 pi 런타임 양쪽에서 검증합니다. 선택한 인증 소스에서 이미지 입력을 지원하는 모델만 사용하며, 설정의 모델 이름에 이미지 지원 여부를 표시합니다. 전송한 이미지는 AI 응답을 위해 선택한 공급자 모델에 전달됩니다. 앱 자체의 별도 클라우드 스토리지는 두지 않고 로컬 대화 `.non/chats/<conversation-id>.json`에도 포함하므로, 선택한 폴더가 iCloud와 동기화되면 대화와 함께 동기화됩니다.

## 스킬

설정의 **스킬**에서 agentskills.io 형식의 `SKILL.md`가 있는 로컬 폴더를 설치할 수 있습니다. 설치 파일은 `~/Library/Application Support/Non/skills/`에 복사되며 문서 폴더나 iCloud에 저장하지 않습니다. 새 스킬은 항상 비활성 상태로 설치되며, 활성화한 스킬의 이름과 설명만 에이전트가 먼저 확인합니다. 현재 작업이 설명과 맞을 때만 전체 지침과 그 지침이 가리키는 상대 경로의 텍스트 자료를 읽습니다.

`aside-browser` v3는 기본 제공되며 최초 실행 때 활성화됩니다. 원본 스킬 파일을 수정하지 않고 그대로 사용합니다. 브라우저나 로그인된 웹사이트, 개인 문맥이 필요한 작업에서는 이 스킬을 읽고 로컬 Aside CLI의 최신 가이드에 따라 작업합니다. Aside CLI 실행은 셸을 거치지 않는 전용 도구로 제한됩니다. 기본 제공 스킬은 끌 수 있지만 삭제할 수 없습니다.

```md
---
name: research-summary
description: 논문과 조사 자료를 근거 중심으로 요약할 때 사용합니다.
---

먼저 출처와 페이지를 확인하고, 사실과 추론을 구분해 작성합니다.
```

폴더 이름은 `name`과 같아야 하며 영문 소문자·숫자·하이픈만 사용합니다. `description`은 AI가 스킬을 선택하는 기준입니다. 스킬은 코드 실행 확장이 아니라 지침과 참조 자료 묶음입니다. 활성 스킬의 내용은 작업에 필요할 때 선택한 AI 제공자에게 전송될 수 있습니다. 삭제하면 설치 폴더를 휴지통으로 이동합니다. 설치 단계에서는 심볼릭 링크를 거부하고 스킬당 2,000개 파일·50MB, 읽는 텍스트 파일당 2MB로 제한합니다.

## 서브에이전트

pi 런타임의 유일한 내부 확장은 `subagent`입니다. 사용자가 확장 패키지를 설치하거나 관리하는 화면은 없습니다. 메인 에이전트는 독립적인 조사가 도움이 될 때 하나의 집중 작업을 위임하거나 최대 4개 작업을 병렬로 실행할 수 있습니다. 각 서브에이전트는 별도 대화 문맥을 사용하고 다시 서브에이전트를 만들 수 없으며, 결과 텍스트만 부모에게 돌려줍니다. 현재는 활성 스킬 읽기와 Aside 사용만 허용해 부모의 노트 쓰기·기억 저장과 충돌하지 않도록 했습니다.

## JSON 노트 형식

Markdown 문자열을 JSON으로 감싼 형식이 아닙니다. 문서 ID·버전·제목과 타입이 있는 블록 배열을 저장합니다.

```json
{
  "format": "non.note",
  "schemaVersion": 1,
  "id": "document-uuid",
  "title": "생각 모음",
  "blocks": [{ "id": "block-uuid", "type": "paragraph", "text": "본문", "props": {} }],
  "createdAt": "2026-09-15T00:00:00.000Z",
  "updatedAt": "2026-09-15T00:00:00.000Z",
  "metadata": {}
}
```

편집기는 Tiptap 3 기반이며 본문 상단에 고정 서식 툴바를 두지 않습니다. `/`를 입력하면 텍스트·제목 1~3·글머리/번호/할 일 목록·인용·코드·구분선·문서 링크를 고르는 메뉴가 커서 옆에 열립니다. `# `·`## `·`- `·`1. `·`> `·코드 펜스 등의 입력 규칙과 굵게·기울임·취소선 단축 입력도 지원합니다. 기존 파일은 열기만 해서는 바뀌지 않으며, 본문을 편집하면 지원되는 블록은 `type: "tiptap"`, `content: <Tiptap JSON node>`로 저장됩니다. 문서의 `non.note` v1 외곽 구조는 유지합니다. `text`는 검색용 보조 텍스트이고 AI는 `content`에서 실제 본문을 추출합니다.

줄 시작에서 `()` 또는 `( )` 뒤에 스페이스를 입력하면 원형 Task가 됩니다. `(x)`·`(X)`는 완료된 Task입니다. `[]` 또는 `[ ]` 뒤에 스페이스를 입력하면 문서 안에서만 쓰는 네모 체크리스트가 되며, `[x]`·`[X]`는 완료 항목입니다. 원형 Task만 왼쪽 **Task** 메뉴의 중앙 페이지에 모이며, 여기서 체크·해제하거나 원본 문서를 열 수 있습니다. 자동 변환 직후 Backspace를 누르면 입력한 기호로 돌아갑니다. 문장 중간·코드 블록에서는 변환하지 않으며 Markdown 원문 편집에는 이 규칙을 적용하지 않습니다.


문서 `metadata`, 블록 ID·추가 필드는 보존합니다. 여러 블록을 하나의 목록으로 합치면 추가 원본 블록 데이터는 `mergedSources`에 보존합니다. 아직 지원하지 않는 노드·서식·속성이나 중첩 `children`을 가진 이전 블록은 보호된 읽기 전용 블록으로 표시하며 편집 중 삭제되지 않게 합니다. 지원하지 않는 문서 버전은 편집하지 않습니다. 외부 파일 갱신 시 편집기 이력을 초기화해 오래된 내용이 실행 취소로 복원되는 일을 막습니다. 제목 입력의 실행 취소는 브라우저 입력 동작이며 Tiptap 본문 이력과 별개입니다. 내부 문서 링크를 지원하며 표·이미지·블록 드래그 UI는 아직 추가하지 않았습니다.

계약은 `src/shared/contracts/note.ts`, 네이티브 파일 경계 검증은 `electron/vault.ts`에 있습니다. AI 읽기/검색은 JSON의 제목과 블록 텍스트를 추출하며 원본 파일을 수정하지 않습니다.

## Markdown 작성·수정

`.md`는 항상 **Tiptap 원문 편집기**로 엽니다. Markdown을 리치 텍스트로 변환해 다시 저장하지 않으므로 프런트매터·표·HTML·위키링크·확장 문법은 원문으로 남습니다. Enter는 줄바꿈, Tab은 탭 문자, `⌘Z`는 실행 취소입니다. 별도의 읽기/편집 전환 버튼 없이 바로 수정하며, 원문에는 고정폭 글꼴을 사용합니다.

JSON과 같은 자동 저장·`⌘S`·외부 변경 감지·충돌 복사본 저장을 사용하며, 복사본도 `.md`로 저장합니다. 편집 시 첫 줄바꿈 형식(LF/CRLF/CR)을 유지하며, 서로 다른 줄바꿈이 섞인 파일은 첫 형식으로 통일합니다. 네이티브 저장은 전달된 UTF-8 원문을 그대로 기록합니다.

제목·본문 검색, `[[위키링크]]` 색인·백링크, AI의 노트 목록·읽기·검색에 Markdown이 포함됩니다. 위키링크 이동은 하단 나가는 링크 패널을 사용합니다. 별도 렌더링 미리보기, 임의 HTML 실행, 로컬 이미지 렌더, 수식, 리치 텍스트 WYSIWYG 편집은 이번 Markdown 범위에 포함하지 않습니다. 내부 `legacy` 종류 이름은 기존 IPC 호환을 위해 유지하지만 읽기 전용을 뜻하지 않습니다.

## 파일 원본 + 로컬 인덱스·백링크

JSON 노트·기존 Markdown·PDF 파일이 원본이며 SQLite는 다시 만들 수 있는 파생 캐시입니다. Electron Node의 `node:sqlite`/FTS5로 제목·본문·별칭(`metadata.aliases`)과 위키링크를 색인합니다. PDF는 파일명과 링크 대상만 지원하며 PDF 본문/OCR은 색인하지 않습니다. 로그인·네트워크 없이 동작합니다.

- `⌘K`: 상단 중앙의 검색 팔레트에서 제목·본문·경로·별칭을 검색합니다. 한글 부분 문자열과 최대 100개 결과를 지원하며 `↑`/`↓`로 이동하고 `Enter`로 열거나 `Esc`로 닫을 수 있습니다.
- Tiptap에서 `[[제목]]` 또는 `[[폴더/파일|표시 이름]]`을 입력하면 내부 링크가 됩니다. 편집기 링크 버튼에서 문서를 선택하면 JSON 노트는 `id:<문서 UUID>`로 연결되어 파일 이동·이름 변경에 영향을 받지 않습니다. PDF/Markdown은 경로로 연결합니다.
- 문서 아래 접을 수 있는 패널에서 백링크·나가는 링크·누락/중복 대상을 확인합니다. 백링크는 링크 발생 횟수 기준이며 자기 자신은 제외합니다. 중복 후보는 사용자가 선택할 수 있지만 원래 링크를 자동 수정하지 않습니다.
- 제목 링크는 루트 경로 → 현재 폴더 경로 → 유일한 제목·파일명·별칭 순으로 해석합니다. `./`와 `../`는 현재 문서 폴더 기준입니다. 중복 제목/ID는 임의로 선택하지 않습니다. `#제목`은 문서까지만 열며 세부 제목·블록 점프는 아직 없습니다.
- 기존 텍스트의 `[[...]]`도 인덱싱되며 나가는 링크 패널에서 열 수 있습니다. 인라인 링크 변환은 새 입력에 적용합니다. 코드·숨긴 폴더·심볼릭 링크·보존된 `mergedSources`는 링크에서 제외합니다.
- 패널이 열린 문서의 저장 완료 및 4초 주기로 파일 변경을 확인하고, 검색/링크 열기 요청도 색인을 갱신합니다. 미저장 내용은 검색·백링크에 반영되지 않습니다. 변경된 파일만 다시 읽으며 파일 읽기 중 변경이나 잘못된 JSON은 경고하고 다음 갱신에 재시도합니다.
- 패널의 새로고침 버튼은 **원본 파일을 수정하지 않고** 인덱스 내용을 재생성합니다. 캐시는 `앱 데이터/indexes/<폴더 경로 SHA256>/index.sqlite`에 저장되며 작업 폴더에는 넣지 않습니다. 기기마다 독립적으로 생성합니다.

이 인덱스 절의 범위는 인덱스와 백링크입니다. Bases형 표 보기는 아래 데이터베이스 절에 설명합니다. 그래프, 연결되지 않은 언급, Markdown 표준 링크 해석, 텍스트 링크 자동 이름 변경은 포함하지 않습니다. 인덱스는 루트별로 분리하며 최대 20,000개 후보 파일/24단계 폴더/문서당 8MB로 제한합니다. 대규모 폴더 성능·SQLite 파일 자체 손상 복구는 추가 검증 범위입니다.

## 기억: 기본 전역 + 폴더 계층

새 기억은 기본적으로 **앱 전역**입니다. `문서/non`을 열기 전에도 관리할 수 있습니다. 특정 폴더에만 적용할 내용은 저장 범위를 해당 폴더로 지정합니다.

`Research/Papers`를 선택하거나 그 안의 문서를 열면 전역 → 현재 폴더 루트 → Research → Research/Papers의 기억 중 관련 항목을 참조합니다. 형제·하위 폴더의 기억은 이 검색에 포함하지 않습니다. 같은 대화에서 이미 언급된 내용은 대화 이력에 남으므로, 기억 검색 범위가 대화 이력을 지우는 보안 경계는 아닙니다.

```text
앱 데이터 (macOS: ~/Library/Application Support/Non/)
  ai-credentials.bin               safeStorage 암호화 인증 정보, 0600
  indexes/<vault-hash>/index.sqlite 검색·링크 캐시, 0600 (동기화하지 않음)
  memory/global/<id>.md             전역 기억
  memory/trash/<id>-<uuid>.md        전역 기억 휴지통

문서/non/
  시작하기.note.json
  Reading.pdf
  .non/
    chats/<conversation-id>.json
    memory/<id>.md                  루트 폴더 기억
    trash/<id>-<uuid>.md
  Research/
    아이디어.note.json
    .non/memory/<id>.md             Research와 그 하위에 적용
    Papers/
      .non/memory/<id>.md           Papers와 그 하위에 적용
```

기억 관리 화면에서 범위·원문을 확인하고 편집하거나 휴지통으로 이동할 수 있습니다. 기존 루트 `.non/memory/`는 루트 폴더 기억으로 그대로 읽으며 자동 이동하지 않습니다. 노트는 JSON이고, 명시적 기억 파일은 현재 사람이 읽을 수 있는 Markdown입니다.

Aside에서 영감을 얻은 명시적 기억 + 대화 시 검색 방식입니다. 관련도·최근성으로 최대 8개를 선택하며 범위별 대표 기억을 우선 확보합니다. 일반 선호는 전역, 폴더 한정 사실은 명시적 폴더 범위로 저장하도록 pi 도구와 프롬프트를 구성했습니다. 검색된 기억은 길이 예산에 맞춰 잘립니다. 임베딩, 자동 압축·통합, 브라우징 이력 수집은 없습니다.

## iCloud와 로컬 저장

기본 `문서/non`의 JSON 노트·PDF·대화·폴더 기억은 해당 위치를 macOS/iCloud가 동기화할 때 함께 동기화됩니다. 앱 자체 동기화 서버는 없습니다. **전역 기억은 현재 기기 로컬이며 iCloud 자동 동기화 대상이 아닙니다.** 인증 정보는 작업 폴더와 분리하고 macOS Keychain 기반 Electron `safeStorage`로 암호화하며 React에 전달하지 않습니다. 테마·사이드바 너비·최근 문서 목록·열린 탭·마지막 대화 선택은 Chromium 로컬 저장소에 둡니다.

노트 저장은 원문 해시 확인 후 같은 폴더의 임시 파일로 교체합니다. 외부 변경 감지는 4초 폴링과 창 포커스 복귀로 수행합니다. 기기 간 동시 편집 병합, 동기화 완료 판정, 엄격한 `NSFileCoordinator`, 클라우드 전용 파일 처리는 미구현/미검증입니다. 일반 JSON 노트 읽기는 8MB, AI 노트 읽기는 2MB, PDF 열기는 50MB 제한이 있습니다.

## 구조

FSD: `app/routes → widgets → features → entities → shared`. Arky의 슬라이스 public API 규칙을 적용하고 shared에는 barrel을 두지 않습니다. TanStack Router·Hotkeys·AI, React, Zustand, es-toolkit, dnd-kit, shadcn 방식의 Radix + Tailwind를 사용합니다. 노트·Markdown·AI 입력은 Tiptap, 대화 표시는 react-markdown, PDF는 PDF.js입니다.

표준 상호작용은 `src/shared/ui`의 shadcn 컴포넌트를 우선합니다. Button·Input·Textarea·Select·Label·Dialog·AlertDialog·Alert·DropdownMenu·ContextMenu·Tooltip을 공용화했으며, 트리 행·탭 드래그 핸들처럼 고유 스타일이 필요한 요소도 `Button unstyled`를 통해 포커스와 disabled 동작을 공유합니다.

Electron main은 폴더·파일 선택, 검증된 파일 IO, 외부 URL, 암호화 인증 저장, 창 생명주기를 담당합니다. renderer는 `contextIsolation`, sandbox, 비활성화된 `nodeIntegration` 상태로 실행되고 preload가 기능별 좁은 IPC만 노출합니다. pi는 창 렌더링을 막지 않도록 Electron이 띄운 별도 Node 유틸리티 프로세스에서 작동하며 요청별 이벤트만 renderer로 전달합니다. renderer의 TanStack AI 어댑터는 이 이벤트를 `RUN_*`, `TEXT_MESSAGE_*`, `CUSTOM` AG-UI 청크로 바꾸며 인증 토큰은 계속 Node 프로세스 안에만 둡니다. pi 모델 레지스트리가 ChatGPT/Claude OAuth와 OpenAI/Anthropic BYOK를 공급자별로 해석하고 갱신합니다. 파일 도구는 기본적으로 `문서/non` 내부만 읽고 쓰며 경로 탈출과 심볼릭 링크를 차단합니다. 사용자가 샌드박스를 끈 요청만 다른 절대경로에 접근할 수 있습니다. 기존 파일 쓰기는 읽었던 원문이 여전히 같은지 확인한 뒤 원자적으로 교체하며 셸 실행 도구는 제공하지 않습니다.

## 파일 기반 데이터베이스 (Bases)

새 노트를 우클릭하거나 파일 트리의 추가 메뉴에서 **데이터베이스**를 선택하면 `.base` YAML 파일을 만듭니다. Markdown의 YAML frontmatter를 읽으며, Non JSON 노트는 `metadata.properties`를 사용합니다. 셀 편집은 원본 파일에 저장하고 Markdown 본문·JSON 확장 필드를 유지합니다. 같은 파일에 대한 동시 저장은 직렬화하고 오래된 revision의 쓰기는 거부합니다.

표·카드·목록·보드와 여러 뷰를 지원합니다. 뷰 순서/복제/기본값, 속성 표시/순서/이름/유형, 중첩 공통·뷰 필터, 다중 정렬과 우선순위, 접을 수 있는 그룹, 결과 제한, 수식, 기본·사용자 정의 요약을 설정할 수 있습니다. 표에서는 Shift 범위 선택, 키보드 이동, TSV 복사/붙여넣기, 값 지우기, 실행 취소/다시 실행, 열 너비·순서 변경 및 파일 동작을 제공합니다. 카드에는 로컬 이미지·HTTPS 이미지·색상 커버와 크기/맞춤/비율, 목록에는 번호/기호·들여쓰기·구분자를 설정할 수 있습니다. 보드 카드를 이동하면 Markdown의 그룹 속성을 변경하며 빈 열 유지·열 순서·열별 새 노트 생성을 지원합니다.

호환 기준은 [Obsidian Bases 형식](https://help.obsidian.md/bases/syntax), [수식 함수](https://help.obsidian.md/bases/functions)와 코어 뷰의 공개 문서입니다. 전역 함수, 날짜/기간, 목록 map/filter/reduce, 정규식·객체, 파일/링크, HTML/이미지/아이콘 값을 해석합니다. 표시는 HTML 정화를 거치며 수식은 허용된 AST만 실행하고 프로토타입·순환 참조·과도한 실행을 차단합니다. 첨부파일 메타데이터, 생성/수정 시각, 내부 링크/백링크/임베드와 읽기 전용 `.obsidian/types.json` 날짜 유형을 인식합니다. Non에서 선택한 속성 유형은 `.base` 속성 설정에 저장합니다.

Markdown의 `![[이름.base#뷰]]`와 fenced `base` 블록은 미리보기 안에 삽입되고, JSON 노트의 base 코드블록·독립된 `.base` 위키 임베드도 렌더링됩니다. `this`는 포함한 노트를 가리킵니다. 인라인 편집은 해당 코드블록만 교체하며 나머지 원문을 보존합니다. CSV/TSV/Markdown 내보내기를 제공합니다.

플러그인·지도 뷰는 범위에서 제외합니다. Obsidian 실행 파일과의 모든 동작에 대한 1:1 차등 검증은 하지 않았습니다. 본문 링크·태그 수집은 Non의 파서이며 Obsidian의 모든 Markdown 구문과 동일하다고 보장하지 않습니다. 수식·YAML의 알 수 없는 확장 설정은 보존합니다. JSON 노트의 `metadata.properties`와 `.base`의 추가 뷰 설정은 Non 확장입니다. 기본 제한은 20,000개 파일/24단계 폴더, 병렬 읽기 6개, 텍스트 64MB, 파일 읽기 8초, 로컬 이미지 8MB입니다.

개발 예제는 `bun run dev:web`의 `/scripts/preview-index.html?bases`에서 사용할 수 있습니다. 테스트는 YAML 및 Markdown 원문 보존, JSON 확장 필드, 안전한 수식 평가, 필터/정렬/요약, 네이티브 파일 생명주기와 동시 저장 충돌을 포함합니다.
