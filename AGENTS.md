# Non

Desktop-only, local-first notes + PDF + AI workspace. Electron, React, TanStack Router, TanStack AI, Zustand, es-toolkit, shadcn/ui. Bun manages development dependencies and bundles the Electron main, preload, and pi utility-process entrypoints; the packaged runtime is Chromium + Node.js and does not require Bun or Rust.

- Use Tiptap for JSON note rich-text editing and Markdown source editing. Preserve each file's format; never round-trip Markdown through rich-text serialization.
- Prefer the shared shadcn/ui layer for every standard interactive control. Extend a shared component when a screen needs a visual variant; use `Button unstyled` for product-specific rows and drag handles so focus/disabled behavior remains centralized. Do not add raw `button`, `input`, `textarea`, `select`, browser confirm, or browser prompt elements outside `src/shared/ui`.
- Style UI with Tailwind utility classes by default. Do not add feature-specific selectors to `styles.css` merely to shorten JSX or group ordinary layout, spacing, color, border, typography, hover, focus, responsive, or dark-mode utilities; use `cn`, shared shadcn variants, or `cva` instead. Add handwritten CSS only when Tailwind cannot express the requirement cleanly, such as global theme/reset tokens or third-party generated DOM that cannot receive class names (for example Tiptap/ProseMirror and PDF.js internals). Keep every unavoidable rule narrowly scoped and document the reason when it is not self-evident.
- Use the shared Hugeicons adapter in `src/shared/ui/icon.tsx` for product icons. Do not import icon packs directly from feature, widget, route, or other shared UI files.
- Use named typography tokens for every text style: Tailwind `text-2xs` through `text-3xl`, `font-*`, `leading-*`, and the semantic document tokens in `styles.css`. Do not add pixel font sizes, arbitrary `text-[Npx]` utilities, literal font weights, line heights, letter spacing, or font families in consumers.

- FSD: app/routes → widgets → features → entities → shared. Public `index.ts` exports only at slice roots; shared uses direct imports. No cross-slice internals or mega-barrels.
- Route segments use folders with `index.tsx` / `route.tsx`. Route-only helpers live in `-ui`, `-model`, etc.
- Strict TypeScript, no `any`. Native filesystem access is validated and bounded to the opened vault.
- Versioned block-based JSON notes, editable Markdown, and PDF files are the source of truth. Preserve unknown JSON extension fields and Markdown source. Memories default to app-global scope; folder memories inherit root → current folder, never siblings. No project entity. Never put credentials or mutable database files in an iCloud vault. Never silently overwrite an external change.
- On launch, create and open the lowercase `non` directory inside the operating system Documents folder. Treat Documents/non as the only workspace root: the sidebar File heading collapses its tree and must not expose a folder picker or alternate-root UI.
- Authentication remains in the local Node utility process; never pass tokens or API keys to React or log them. Collect BYOK values through the native macOS secret prompt, encrypt all stored credentials with Electron `safeStorage`, and move decrypted values only across the private main ↔ utility-process channel. Keep the renderer sandboxed with context isolation and expose only narrow, validated preload APIs.
- Frontend chat state and streaming use `@tanstack/ai-react` `useChat`. Bridge Electron pi IPC through the custom AG-UI `ConnectConnectionAdapter`; do not restore parallel hand-written renderer message, loading, or cancellation state.
- Agent filesystem tools are sandboxed to Documents/non by default. Keep traversal and symbolic-link escape blocked while the sandbox is enabled. When the user explicitly disables it in settings, absolute-path UTF-8 file reads and guarded atomic writes outside the vault are allowed, but shell execution remains unavailable. Existing files must be read first and written with exact prior content so external changes are never silently overwritten.
- `bun run check`, `bun run test`, `bun run build:ui`, and `bun run build` validate changes. Use `bun run dev:web` for fast renderer work with the in-memory sample vault, and `bun run dev` for native filesystem, PDF, authentication, agent IPC, and final Electron validation. Browser UI is only a developer harness, not a supported web product.
